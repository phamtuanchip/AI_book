Phần III — Công nghiệp Agentic: AI Agents trong công việc

Chương 12: AI agent là gì

Ở Chương 9, bạn đã thấy một CLI agent tự đọc-sửa-chạy lệnh nhiều vòng để hoàn thành một yêu cầu. Đó chính là một ví dụ cụ thể của khái niệm rộng hơn: AI agent. Phần III mở rộng khái niệm này ra ngoài phạm vi lập trình, và Phần IV sẽ áp dụng nó có hệ thống vào toàn bộ SDLC.

Khác biệt giữa chatbot và agent

Một chatbot/prompt đơn lẻ nhận input, trả lời một lần, dừng lại — con người đọc kết quả rồi tự quyết định bước tiếp theo. Một agent có thêm ba khả năng chatbot thường không có:

  • Dùng công cụ (tools): agent có thể gọi hàm/API thật — đọc file, truy vấn database, gọi web search, chạy lệnh terminal — chứ không chỉ sinh văn bản.
  • Tự lập kế hoạch nhiều bước: agent tự chia một mục tiêu lớn thành các bước nhỏ (giống task decomposition ở Chương 6), không cần con người ra lệnh từng bước một.
  • Tự quan sát & điều chỉnh: agent nhìn vào kết quả của bước vừa làm (test fail, API trả lỗi, file không tồn tại) để quyết định bước tiếp theo, lặp lại đến khi đạt mục tiêu hoặc gặp giới hạn (số vòng lặp, quyền hạn, thời gian).

Vòng lặp cốt lõi: Plan → Act → Observe

Ví dụ cụ thể với CLI coding agent từ Chương 9: Plan — "cần đọc file config trước khi sửa"; Act — gọi tool đọc file; Observe — thấy file dùng thư viện X; Plan lại — "cần sửa theo API của thư viện X"; Act — sửa file, chạy test; Observe — test fail vì thiếu import; Plan lại — thêm import... cứ thế đến khi test pass.

Hai thành phần bắt buộc: Tools và Memory

Tools (công cụ)

Tools là "tay chân" của agent — mỗi tool là một hàm có tên, mô tả, và tham số, được định nghĩa rõ để mô hình biết khi nào và cách nào gọi nó. Ví dụ: read_file(path), run_command(cmd), search_web(query), send_email(to, subject, body). Mô hình không "biết cách" gọi tool bẩm sinh — nó được huấn luyện để nhận diện khi nào một yêu cầu cần tool, chọn tool phù hợp, và tạo ra lời gọi đúng định dạng mà hệ thống xung quanh nó hiểu được.

Memory (bộ nhớ)

Vì context window có giới hạn (Chương 2), agent cần cơ chế "nhớ" vượt ra ngoài một lần gọi:

  • Bộ nhớ ngắn hạn: lịch sử hội thoại/các bước đã làm trong phiên hiện tại, nằm trong context window.
  • Bộ nhớ dài hạn: thông tin lưu lại giữa các phiên (sở thích người dùng, quy ước dự án — giống file CLAUDE.md ở Chương 9), thường lưu ngoài context window và được "nạp" lại khi cần.

Bộ nhớ dài hạn trong thực tế trông như thế nào

Cụ thể hoá khái niệm "bộ nhớ dài hạn" ở trên bằng hai cách triển khai phổ biến:

  • Key-value đơn giản: lưu các sự thật rời rạc dạng khoá-giá trị (ví dụ "ngôn ngữ ưa thích: TypeScript", "quy ước đặt tên: camelCase") — phù hợp thông tin ít, thay đổi chậm, giống hệt file CLAUDE.md ở Chương 9.
  • Vector store (kho vector): lưu văn bản dưới dạng embedding (Chương 2) để tìm kiếm theo ngữ nghĩa — phù hợp khi lượng thông tin lớn, cần tìm "đoạn nào liên quan nhất" thay vì tra đúng một khoá cố định. Đây chính là nền tảng kỹ thuật của RAG sẽ nói kỹ ở Chương 13.

Một agent thật thường dùng cả hai: key-value cho vài quy tắc cố định quan trọng, vector store cho kho tri thức lớn cần tra cứu linh hoạt.

Vì sao khái niệm này quan trọng ngoài lập trình Một khi đã hiểu agent = mô hình + tools + vòng lặp plan-act-observe + memory, bạn sẽ thấy nguyên lý này áp dụng được cho bất kỳ công việc nào có thể mô tả thành các bước dùng công cụ — không riêng gì coding. Chương 15 sẽ đưa ra ví dụ cụ thể ngoài lập trình.

Giới hạn cần nhớ ngay từ đầu

Agent mạnh hơn chatbot đơn lẻ, nhưng đi kèm rủi ro lớn hơn tương ứng: một chatbot trả lời sai chỉ tốn thời gian đọc lại; một agent hành động sai có thể xoá nhầm dữ liệu, gửi nhầm email, hay chạy lệnh phá vỡ hệ thống thật — vì nó thực sự thực thi, không chỉ đề xuất. Đây là lý do Chương 16 dành hẳn để nói về quản trị và giới hạn quyền hạn, trước khi Phần IV đưa agent vào quy trình SDLC thật.

Bài tập nhỏ Nhớ lại một lần bạn dùng CLI coding agent (Chương 9) hoặc agent bất kỳ. Vẽ lại (trên giấy hoặc mô tả bằng lời) đúng 3 bước Plan → Act → Observe mà nó đã thực hiện trong lần đó. Nếu chưa dùng agent nào, hãy thử với một CLI coding agent cho 1 tác vụ nhỏ, rồi làm bài tập này.
