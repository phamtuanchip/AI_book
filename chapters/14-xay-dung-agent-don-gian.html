Phần III — Công nghiệp Agentic: AI Agents trong công việc

Chương 14: Xây dựng agent đơn giản

Chương này đi từ lý thuyết (Chương 12-13) sang thực hành: xây một agent single-agent tối giản bằng mã giả (pseudocode) để thấy rõ vòng lặp Plan → Act → Observe được lập trình thế nào bên dưới các công cụ bạn đã dùng. Cú pháp SDK cụ thể thay đổi theo nhà cung cấp và phiên bản — hãy đọc phần này để hiểu nguyên lý, rồi tra tài liệu SDK chính thức (Claude Agent SDK/API, hoặc SDK tương đương) khi triển khai thật.

Hai lựa chọn: viết bằng SDK, hay dùng công cụ no-code

  • SDK/API (Claude Agent SDK, Messages API với tool use...): kiểm soát tối đa, tích hợp sâu vào hệ thống nội bộ, phù hợp khi cần logic nghiệp vụ riêng hoặc bảo mật chặt. Cần biết lập trình.
  • Công cụ no-code/low-code (nền tảng automation có tích hợp AI, workflow builder kéo- thả): dựng nhanh, phù hợp prototype hoặc tự động hoá quy trình đơn giản, không cần viết code. Đánh đổi là ít kiểm soát chi tiết hơn và phụ thuộc vào nền tảng.

Phần còn lại của chương minh hoạ bằng SDK vì nó bộc lộ rõ nhất cơ chế bên trong — nhưng nguyên lý vòng lặp áp dụng y hệt dù bạn dùng công cụ nào.

Định nghĩa tool cho agent

Mỗi tool cần: tên, mô tả (để mô hình biết khi nào nên dùng), và schema tham số. Ví dụ định nghĩa 2 tool cho một agent hỗ trợ vận hành đơn giản:

tools = [
  {
    name: "get_order_status",
    description: "Tra cứu trạng thái đơn hàng theo mã đơn hàng.",
    input_schema: {
      order_id: "string, bắt buộc"
    }
  },
  {
    name: "send_notification",
    description: "Gửi thông báo cho khách hàng qua email.",
    input_schema: {
      email: "string, bắt buộc",
      message: "string, bắt buộc"
    }
  }
]

Vòng lặp agent tối giản (mã giả)

conversation = [system_prompt, user_message]

while chưa_xong and số_vòng_lặp < giới_hạn:
    response = call_model(conversation, tools)

    if response chứa tool_call:
        for mỗi tool_call trong response:
            result = execute_tool(tool_call.name, tool_call.input)
            conversation.append(tool_call)
            conversation.append(tool_result: result)
        # quay lại đầu vòng lặp — mô hình "Observe" kết quả tool
    else:
        # mô hình trả lời bằng văn bản thường → coi như đã xong
        chưa_xong = False
        final_answer = response.text

return final_answer

Đối chiếu với sơ đồ Plan → Act → Observe ở Chương 12: call_model chính là bước Plan (mô hình quyết định bước tiếp theo, có thể là gọi tool hoặc trả lời), execute_tool là Act, và việc đưa tool_result trở lại conversation chính là Observe — mô hình "nhìn thấy" kết quả ở vòng lặp kế tiếp.

Xử lý khi tool thất bại

Mã giả ở trên giả định execute_tool luôn thành công — thực tế, tool có thể lỗi (API bên ngoài timeout, tham số không hợp lệ, quyền truy cập bị từ chối). Vòng lặp agent cần xử lý rõ ràng thay vì để lỗi làm sập toàn bộ phiên:

for mỗi tool_call trong response:
    try:
        result = execute_tool(tool_call.name, tool_call.input)
        conversation.append(tool_result: result, is_error: false)
    except ToolError as e:
        # Đưa lỗi trở lại cho mô hình như một "Observe" bình thường —
        # agent có thể tự quyết định thử cách khác, không phải luôn cần
        # con người can thiệp ngay lập tức
        conversation.append(tool_result: e.message, is_error: true)

Đưa lỗi trở lại context (thay vì crash chương trình) cho phép mô hình tự "Observe" và điều chỉnh kế hoạch ở vòng lặp tiếp theo — ví dụ thử tham số khác, hoặc báo cáo với con người nếu đã thử nhiều cách không thành công (đúng giới hạn số vòng lặp bên dưới).

Structured output — ép đầu ra theo đúng schema

Với các bước cần dữ liệu có cấu trúc rõ ràng để hệ thống xung quanh xử lý tiếp (ví dụ orchestrator ở Chương 13 cần agent trả về đúng JSON để chuyển cho bước sau), nên ràng buộc mô hình trả lời theo đúng schema thay vì hy vọng nó tự định dạng đúng:

Yêu cầu: Trả lời DUY NHẤT một JSON object đúng theo schema sau, không
kèm giải thích thêm:
{
  "status": "success" | "needs_review" | "failed",
  "summary": string,
  "next_action": string | null
}

Nhiều SDK/framework agent hỗ trợ khai báo schema tường minh (thay vì chỉ mô tả bằng lời trong prompt) — cách này đáng tin cậy hơn nhiều so với yêu cầu bằng văn bản tự nhiên, đặc biệt khi output cần được một chương trình khác đọc và xử lý tiếp (ví dụ orchestrator ở Chương 22).

Giới hạn số vòng lặp là bắt buộc, không phải tuỳ chọn Không có giới_hạn số vòng lặp, một agent có thể lặp vô hạn (gọi tool, thất bại, thử lại, thất bại...) nếu gặp tình huống nó không tự thoát ra được — vừa tốn chi phí (mỗi vòng lặp là một lần gọi mô hình, tính phí theo token) vừa có thể gây hành động lặp lại không kiểm soát (ví dụ gửi email trùng nhiều lần). Luôn đặt giới hạn cứng.
Template — System prompt cho agent chuyên biệt 
Bạn là {tên vai trò agent}, chuyên trách {phạm vi công việc cụ thể}.

Mục tiêu: {mục tiêu agent cần đạt được trong mỗi phiên làm việc}.

Bạn có các công cụ sau: {liệt kê tool và khi nào nên dùng từng tool}.

Ràng buộc:
- Chỉ hành động trong phạm vi: {liệt kê rõ việc được làm}.
- Không được: {liệt kê rõ việc KHÔNG được làm, đặc biệt hành động khó
  hoàn tác — xoá dữ liệu, gửi tiền, deploy production}.
- Nếu không chắc chắn hoặc thiếu quyền hạn cho một hành động, dừng lại
  và hỏi con người thay vì tự đoán.

Khi hoàn thành hoặc gặp bế tắc, tóm tắt rõ: đã làm gì, kết quả ra sao,
còn việc gì cần con người xử lý tiếp.

Ví dụ chạy thật: theo dõi một phiên làm việc cụ thể

Áp vòng lặp mã giả ở trên vào ví dụ cụ thể: người dùng yêu cầu "Kiểm tra đơn hàng #4471, nếu bị trễ giao hàng thì báo cho khách qua email". Sơ đồ tuần tự dưới đây cho thấy từng lượt gọi thật:

Từ agent tối giản đến agent dùng được thật

Agent mã giả trên đủ để hiểu nguyên lý, nhưng thiếu nhiều thứ một agent chạy thật cần có — sẽ được bàn kỹ ở Chương 16 và Chương 23: xử lý lỗi khi tool thất bại, giới hạn quyền hạn theo nguyên tắc least- privilege, log lại toàn bộ hành động để audit, và điểm dừng để con người phê duyệt trước hành động rủi ro cao.

Bài tập nhỏ Chọn một việc lặp lại trong công việc của bạn có thể mô tả bằng 2-3 tool đơn giản (ví dụ: tra cứu thông tin, gửi thông báo, cập nhật trạng thái). Viết ra: (1) danh sách tool với mô tả rõ ràng, (2) system prompt theo template trên, (3) ít nhất 2 ràng buộc "không được làm" quan trọng nhất cho agent đó.
